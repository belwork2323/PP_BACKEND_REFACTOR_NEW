RAW MATERIAL PREPARATION PREMIX ASSET API (BRUNO)
=================================================

1. TRIGGER THROUGH THE ACEM BACKEND
-----------------------------------

Use this request to exercise the approval flow. The backend queues the
corresponding asset after saving the approval.

Method: POST
URL: {{acemBaseUrl}}/api/v1/approver/form/premix/change-status
Headers:
  Content-Type: application/json
  Authorization: Bearer {{approverToken}}

Body:

{
  "formId": "RMPF-2026-0017",
  "premixNo": 1,
  "subDepartmentId": 3,
  "actionType": "APPROVED",
  "remarks": "Premix verified and approved"
}

Successful response: 200 OK

{
  "success": true,
  "code": 200,
  "message": "Premix approved successfully",
  "data": {
    "formId": "RMPF-2026-0017",
    "batchId": "BATCH-2026-0042",

Set `formId` and `premixNo` to an entry currently waiting for approval. After
ACEM saves the approval, the microservice immediately attempts the gateway
POST. Failed deliveries remain queued for scheduled retries. Its receipt is
retained with the RMP form and is not added to this response.

2. ASSET GATEWAY REQUEST / RESPONSE
----------------------------------

Configure these Bruno environment variables:

  assetGatewayUrl  Base URL of the asset gateway, for example http://172.16.69.88:8080
  peerSrt          Gateway peer_srt credential (store in a local/private environment)
  assetUserId      Gateway userid, normally admin

Request
-------

Method: POST
URL: {{assetGatewayUrl}}/gateway/api/v1/assets/
Headers:
  Content-Type: application/json
  peer_srt: {{peerSrt}}
  userid: {{assetUserId}}

Notes
-----

- The backend generates one asset per approved premix. Replace the final ID
  segment with that premix number for other premixes.
- Slashes in a batch ID are converted to hyphens for the asset ID CRN segment.
  For example, batch `ACEM/2609/0007` becomes `ACEM-2609-0007` in the asset ID;
  `subjectId` remains `ACEM/2609/0007`.
  Its premix 1 asset ID is `uid:acem:asset/ACEM-2609-0007:RMPF-2026-051/1`.
- The payload contains only the approved premix and weightment rows for it.
- Form status and submission fields reflect the saved form state at approval.
- The retry worker uses the same POST and asset ID for delivery retries.


3. LIST REGISTERED BLOCKCHAIN TRANSACTIONS
------------------------------------------

Method: POST
URL: {{acemBaseUrl}}/api/v1/admin/blockchain/list
Headers:
  Content-Type: application/json
  Authorization: Bearer {{adminToken}}

Request body (first page of registered events):

{
  "page": 1,
  "pageSize": 10
}

Optional filters: `search`, `eventType`, `department`, `subDepartment`,
`startDate`, and `endDate`. Results are sorted newest first. Successful
gateway asset registrations appear after the delivery worker records their
receipt in `blockchain_events`.

Success response: 200 OK

{
  "success": true,
  "code": 200,
  "message": "Blockchain transactions fetched successfully",
  "data": {
    "events": [
      {
